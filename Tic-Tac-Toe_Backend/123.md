##Задание 1. Добавление БД

1. Требовалось: описать подключение к PostgreSQL в application.properties.
Сделано в application.properties:
```
spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5432/tictactoe}
spring.datasource.username=${DB_USERNAME:postgres}
spring.datasource.password=${DB_PASSWORD:postgres}
spring.datasource.driver-class-name=org.postgresql.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.open-in-view=false
```
Как работает: приложение по умолчанию подключается к локальной базе tictactoe под пользователем postgres с паролем postgres. Если нужно, можно переопределить через переменные окружения DB_URL, DB_USERNAME, DB_PASSWORD.

Таблицы вручную создавать не нужно: spring.jpa.hibernate.ddl-auto=update говорит Hibernate создать/обновить таблицы по JPA-сущностям при старте приложения.

2. Требовалось: избавиться от класса-хранилища.
Сделано частично совместимо: backend теперь использует JPA-репозиторий через JpaCurrentGameRepository.java, который работает с CurrentGameJpaRepository.java.

Старый CurrentGameStorage.java и InMemoryCurrentGameRepository.java физически пока остались в проекте, но из DI они больше не используются. В ApplicationConfig.java подключён именно JpaCurrentGameRepository.

Как работает сейчас: CurrentGameServiceImpl обращается к интерфейсу CurrentGameRepository, а реальная реализация подставляется JPA-адаптером. Игра сохраняется в PostgreSQL.

3. Требовалось: добавить специальные аннотации для классов, которые сохраняются в БД.
Сделано:

CurrentGameData.java
```java
@Entity
@Table(name = "current_games")
```
UserData.java
```java
@Entity
@Table(name = "users")
```
GameFieldData.java
```java
@Embeddable
```
Как работает: CurrentGameData и UserData становятся таблицами в PostgreSQL. GameFieldData встраивается в таблицу current_games, а игровое поле хранится в колонке cells как строка из 9 цифр.

4. Требовалось: использовать CrudRepository у репозиториев.
Сделано:

CurrentGameJpaRepository.java

public interface CurrentGameJpaRepository extends CrudRepository<CurrentGameData, UUID>
UserJpaRepository.java

Как работает: Spring Data сам создаёт реализацию этих интерфейсов во время старта приложения. Мы вызываем save, findById, findByLogin, existsByLogin, а Spring Data генерирует SQL-запросы.

Отдельный Frontend Для Проверки

По твоему уточнению backend не должен обслуживать frontend, поэтому проверялка лежит отдельно:

front/index.html
front/server.js
front/README.md

Как запускать:

node front/server.js
Открыть:

http://localhost:3000
Зачем нужен server.js: если открыть HTML напрямую, браузер может заблокировать запросы с Authorization из-за CORS. server.js проксирует /api/* на backend http://localhost:8080, не требуя никаких правок в backend ради frontend.

Как Проверить БД

Ты уже создал базу. Таблиц до первого успешного старта может не быть. Это нормально.

После запуска backend проверить таблицы:

psql -U postgres -h localhost -p 5432 -d tictactoe -c "\dt"
Должны появиться примерно:

current_games
users
